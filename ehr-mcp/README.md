# Patient EHR & Context MCP Server

A production-quality Model Context Protocol (MCP) server that exposes patient medical context and semantic RAG search to AI agents through a secure, controlled interface.

## 🎯 Purpose

This server ensures that AI agents **never directly access the patient database**. Instead, all medical data flows through this MCP server, which strictly enforces:

- **Server-Side Authorization**: Every data-returning tool call validates `token: str` server-side against `AGENT_API_TOKEN`. Callers cannot bypass checks with boolean flags.
- **Structured Error Responses**: Deterministic JSON error shapes (no raw stack traces or silent `None`).
- **Separation of Concerns**: Complete separation between SQLite database logic in `database.py` and MCP protocol handlers in `server.py`.
- **RAG Semantic Search**: Dense vector retrieval over patient narratives (demographics, conditions, allergies, active prescriptions) and cross-server unified search integrated with `clinical-mcp`.

## 🚀 Setup & Execution

### 1. Install Dependencies

```powershell
cd ehr-mcp
python -m pip install -r requirements.txt
```

### 2. Configure Environment

Copy `.env.example` to `.env`:

```powershell
cp .env.example .env
```

Ensure `AGENT_API_TOKEN` and `MONGO_URI` are set:
```env
AGENT_API_TOKEN=medical-agent-secret-token
MONGO_URI=mongodb+srv://karthik:karthik@projects.ktwm3ms.mongodb.net/?appName=projects
MONGO_DATABASE=clinical_knowledge
MONGO_PATIENT_RAG_COLLECTION=patient_chunks
```

### 3. Seed Demo Data & RAG Vectors

```powershell
python seed_data.py
```

This populates `patients.db` with 3 realistic clinical patients (`P001`, `P002`, `P003`) and generates normalized vector embeddings in MongoDB Atlas.

### 4. Run Automated Tests

```powershell
python -m pytest test_ehr_mcp.py -v
```

### 5. Start the Server

```powershell
python server.py
```

## 🐍 Python MCP Client Usage Snippet

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    server_params = StdioServerParameters(
        command="python",
        args=["server.py"],
        cwd="d:/sih2026/ehr-mcp"
    )
    async with stdio_client(server_params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            
            # 1. Read resource (lower sensitivity)
            profile = await session.read_resource("patient://profile/P001")
            print("Profile Resource:", profile)
            
            # 2. Call authenticated tool
            prescriptions = await session.call_tool(
                "fetch_active_prescriptions",
                {"patient_id": "P001", "token": "medical-agent-secret-token"}
            )
            print("Prescriptions Tool:", prescriptions)

asyncio.run(main())
```

## 🛠️ API Reference

### Resources

#### `patient://profile/{patient_id}`
Returns demographics, documented allergies, and diagnosed conditions.
> **Note on Sensitivity:** MCP resources in this specification do not have per-call parameter authorization ergonomics. Hence, this resource only exposes baseline demographics and conditions; sensitive prescriptions and emergency contacts require authenticated tool calls.

### Tools (All require `token: str`)

| Tool Name | Parameters | Description |
| :--- | :--- | :--- |
| `fetch_active_prescriptions` | `patient_id: str, token: str` | Returns all currently active medications with dosage and frequency. |
| `get_allergies` | `patient_id: str, token: str` | Returns list of documented patient allergies. |
| `get_medical_conditions` | `patient_id: str, token: str` | Returns list of chronic medical conditions. |
| `get_emergency_contact` | `patient_id: str, token: str` | Returns primary emergency contact (name, phone, relationship). |
| `search_patient_records` | `query: str, token: str, limit: int = 5` | Semantic RAG vector search across patient medical histories. |
| `unified_healthcare_search` | `query: str, token: str, limit: int = 5` | Cross-server search joining EHR patient context with Clinical reference guidelines. |

## ⚠️ Error JSON Shapes

All errors conform to predictable structured contracts:

#### Unauthorized (Invalid or missing token)
```json
{
  "error": "Unauthorized",
  "code": "UNAUTHORIZED",
  "message": "Invalid or missing authorization token"
}
```

#### Patient Not Found
```json
{
  "error": "Patient 'P999' not found",
  "code": "PATIENT_NOT_FOUND",
  "message": "No patient with ID 'P999' exists in the system"
}
```

#### Missing Parameter
```json
{
  "error": "Missing patient_id parameter",
  "code": "MISSING_PARAMETER"
}
```

## 🔒 Security Notes Before Production

1. **Token Replacement**: The fixed `AGENT_API_TOKEN` is intended for local hackathon development. In production, replace this with OAuth 2.0 / JWT bearer tokens validated against an enterprise Identity Provider (Okta, Keycloak, Azure AD).
2. **Per-Agent Scoping**: Implement role-based access control (RBAC) and attribute-based access control (ABAC) to restrict each AI agent to specific patient panels or clinical departments.
3. **Audit Logging**: Implement tamper-evident audit trails recording every read, tool call, query timestamp, and agent ID for HIPAA / GDPR compliance.
4. **Encryption**: Enforce TLS encryption in transit for network transports and AES-256 encryption at rest for `patients.db` and MongoDB Atlas.
